# Sample Analysis: Coverage and Gaps

This review uses the smallest supplied export, `samples/sample-small.xml`, and its existing local output at `output/sample-small/`. Counts describe the records in this export, not necessarily the final FileMaker application state: it contains both `AddAction` and partial `ModifyAction` records.

## What the current analysis establishes

- Input is `FMSaveAsXML` version `2.2.2.0`, generated by FileMaker `21.0.1`, UTF-16 LE with BOM. `DDR_INFO` is absent.
- The inventory sees 17 catalog families, including 13 accounts, 6 privilege sets, 13 base tables, 51 table occurrences, 35 relationships, 187 field records, 148 scripts, 45 layout records, and 1,160 layout objects. Field/layout totals include source modifications.
- The existing extraction retains source action/properties and detached details: 2,120 script steps across 113 groups, 36 custom-function bodies, and 15 value-list option records.
- Current script analysis emits call/navigation/read/write edges, basic structured control flow, step-effect and variable findings. It also marks disabled steps and unreachable-step candidates; these are static candidates, not executed behavior.

## DDR export comparison

The present sample cannot answer whether a DDR adds information: it has no `DDR_INFO`, and no DDR export for the same database is available in the repository. Claris documents `Save a Copy as XML` and DDR as separate outputs. Save-as-XML can include extra analysis details (`DDR_INFO`); DDR XML lets the user select report elements, and HTML contains a subset of DDR XML. Therefore “DDR is always richer” is not established.

To resolve this gap, create both a Save-a-Copy-as-XML export with **Include details for analysis tools** enabled and a DDR XML with all relevant elements selected, from the same FileMaker version and database. Compare coverage for calculations/references, script steps/parameters, relationships, layouts, accounts/privileges, and external sources. Preserve each source as a separate format; if DDR support is worthwhile, implement it as a distinct adapter and compare normalized outputs rather than merging unlike XML structures.

References: [Claris: Documenting database schemas](https://help.claris.com/en/pro-help/content/documenting-schemas.html); [Claris FileMaker Pro 19 DDR XML grammar](https://help.claris.com/archive/fm19/en/pro-db-design-report-xml-grammar/).
